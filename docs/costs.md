# ต้นทุนต่อหน่วย (อัปเดต 2026-08-09)

ตัวเลขสำหรับตั้งราคาและรู้ว่า free tier จะตันเมื่อไหร่ — ทบทวนทุกครั้งก่อนรับไซต์ใหม่

## ค่าคงที่รายเดือน (สถานะปัจจุบัน)

| บริการ | ตอนนี้ | เมื่อมีไซต์จริง |
|---|---|---|
| Vercel | ฟรี (Hobby) | Pro $20/เดือน เมื่อเริ่มเก็บเงินลูกค้า (เงื่อนไข non-commercial ของ Hobby) |
| Supabase | ฟรี | Pro $25/เดือน เมื่อชนลิมิต (DB 500MB / Storage 1GB / egress) |
| Railway (worker) | trial $5 (~30 วัน — **หมดประมาณต้นก.ย. 2026 ต้องอัปก่อนถึงวันนั้น**) | Hobby $5/เดือน |
| LINE Messaging API | ยังไม่ใช้ | ฟรี 200 push/เดือน/OA → แพ็กเริ่ม ~1,200 บาท/เดือน (จึงต้องกรองหลอกให้ดี — ADR-006) |

## ต้นทุนผันแปร: Gemini (ตัวหลักที่สเกลตามกล้อง)

สมมติฐานต่อกล้อง (โหมด event จากกล้อง/NVR — ไม่ใช่ agent ทดสอบ):
- กล้องทั่วไปยิง event จริง ~50–150 ครั้ง/วัน (หลังกรองด้วย Smart Event ของกล้องแล้ว)
- 1 ภาพ ≈ 1,000–1,500 token input + prompt ~700 token + output ~100 token

ประมาณการต่อกล้อง/เดือน (รุ่น flash ราคาถูกสุด ณ ต้นปี 2026 อยู่ราว $0.3–0.6 ต่อล้าน token input):
- 100 event/วัน × 30 วัน × ~2,000 token ≈ 6M token/เดือน/กล้อง
- ≈ **$2–4 (70–150 บาท) ต่อกล้อง/เดือน** — ขายแพ็กเกจ 1,990 บาท (ADR-009) ครอบ 6 กล้องยังเหลือ margin สบาย

**จุดต้องทำก่อนไซต์นำร่อง:** เปิด billing บน Google AI Studio (ผูกบัตร) — free tier ชน 429 ตั้งแต่กล้องเดียว (พิสูจน์แล้ว 2026-08-09) ระบบมี throttle + fallback ช่วยแต่ไม่พอสำหรับงานจริง

## กันชนที่มีในระบบแล้ว
- Retention 60 วัน (ADR-012) คุม storage ไม่ให้โตไม่จำกัด
- สวิตช์รายกล้อง (ADR-011) — ลูกค้าจ่ายเฉพาะกล้องที่เปิด = ต้นทุน Gemini ตามจำนวนที่เก็บเงินได้จริง
- VLM throttle 7 วิ/ภาพ + fallback รุ่น lite เมื่อโดน rate limit

# วัดจริงจากไซต์สำนักงานใหญ่ (อัปเดต 2026-08-19)

ตัวเลขข้างบนเป็นการประมาณตอนยังไม่มีกล้องจริง — ด้านล่างคือของจริงจาก `npm run stats`

## ต้นทุน AI ต่อกล้อง — ผูกกับ "ความวุ่นวายของภาพ" ไม่ใช่จำนวนกล้อง

| กล้อง | event/วัน | เรียก AI/วัน | บาท/เดือน |
|---|---|---|---|
| ช่อง 1 ลานจอด (นอกอาคาร) | ~250 | ~186 | **75** |
| ช่อง 16 สำนักงาน | ~129 | ~62 | **25** |
| ช่อง 7 สำนักงาน | ~124 | ~60 | **25** |

**กล้องนอกอาคารแพงกว่ากล้องในห้อง ~3 เท่า** (รถวิ่ง คนเดิน แสงเปลี่ยน สัตว์ ทั้งวันทั้งคืน)
ต้นทุนต่อครั้ง = 0.0135 บาท (prompt 2,738 tokens + ภาพ 2 ใบ 516 + คำตอบ 150 ที่เรต flash-lite $0.10/$0.40 ต่อล้าน token)
**ข้อสังเกต: 84% ของค่าใช้จ่ายคือ prompt ของเราเอง ไม่ใช่รูป** → context caching (ลดได้ถึง 90%) คือช่องทางลดต้นทุนที่ยังไม่ได้ใช้

## สูตรตีต้นทุนที่ใช้ได้จริง

```
ต้นทุนรวม/เดือน = ค่าคงที่ ~1,800 บาท (แชร์ทุกโครงการ) + 50 บาท × จำนวนกล้อง
```
ค่าคงที่ = Vercel Pro 700 + Supabase Pro 875 + Railway 175 (+ LINE ~1,200 เมื่อ push เกิน 200/เดือน)

**ต้นทุนต่อกล้องไม่คงที่ — มันลดลงเมื่อไซต์ใหญ่ขึ้นและเมื่อมีลูกค้าหลายราย:**

| สถานการณ์ | ต้นทุนรวม/เดือน | ต่อกล้อง |
|---|---|---|
| 1 ไซต์ 3 กล้อง (วันนี้) | ~1,935 | **645** ⚠️ เกิน 500 |
| 1 ไซต์ 12 กล้อง | ~2,400 | **200** |
| 5 ไซต์ 60 กล้อง | ~5,650 | **94** |
| 10 ไซต์ 120 กล้อง | ~9,200 | **77** |

**บทสรุปสำหรับการตั้งราคา:** เพดาน 500 บาท/กล้อง ปลอดภัยมากตั้งแต่ไซต์ที่มี 6 กล้องขึ้นไป
แต่**ไซต์เล็กกว่า 5 กล้องขาดทุนถ้าคิดต่อกล้องล้วน ๆ** → ต้องมีค่าขั้นต่ำต่อโครงการเสมอ (สอดคล้อง ADR-009 ที่ขายเป็นแพ็กเกจต่อโครงการ ไม่ใช่ต่อกล้อง)

## ยังไม่มีเพดานต่อกล้อง (ความเสี่ยงที่รู้ตัว)
กล้องที่วุ่นผิดปกติ (ต้นไม้ไหวทั้งวัน ฝนตก) กินงบได้ไม่จำกัด — ควรทำเพดาน "เรียก AI ได้ไม่เกิน N ครั้ง/วัน/กล้อง" ก่อนเซ็นสัญญาราคาคงที่
